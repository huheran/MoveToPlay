# 本机训练流水线试验记录（2026-08-08）

## 环境

- Windows 11
- Python 3.13.9（隔离环境 `.venv-training`）
- scikit-learn 1.7.2
- numpy 2.3.5
- pandas 2.3.3
- scipy 1.16.3
- joblib 1.5.3
- 本机未安装 Docker；Dockerfile 已生成，实际验证使用与其相同的固定 Python 依赖。

## 数据版本发现

恢复的数据中存在两个有明确意义的版本：

1. `movetoplay-deployed-v1`
   - 当前固件模型实际使用的数据快照。
   - 1,177,590 条样本、1,665 条事件。
   - 对应加入 zhq10/zhq11 之前的 processed 备份。
2. `movetoplay-latest-v2`
   - 朋友最近提供的最终 processed 文件。
   - 1,218,686 条样本、1,722 条事件。
   - 比 deployed-v1 多 zhq10、zhq11 两个会话，尚未被当前固件模型使用。

历史数据的 `event_id` 仅在单个 session 内唯一；跨 session 有 385 个重名，
但 `(session_id, event_id)` 没有重复。未来服务器上传应生成全局唯一事件 ID。

## 资源观察

- 特征构建阶段观察到约 2.9 GB 进程内存峰值。
- 云端训练容器最低建议 4 GB，实际建议至少 8 GB 内存。
- 当前随机森林训练不需要 GPU。

## 尚未包含的远程功能

- Companion 的数据采集界面和上传客户端。
- 服务器认证、分片/断点上传、对象存储和任务队列。
- 原始 session 到新 processed 数据集版本的显式构建器。
- Python 与固件 C 推理逐窗口预测一致性测试。

这些功能应建立在当前已经验证的训练入口之上，不应把网络上传逻辑混入模型训练脚本。
